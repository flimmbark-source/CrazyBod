Locked implementation contract

Progression

The first run begins with 5 capacity.

The first run’s final score is deposited into the persistent bank.

The skill tree unlocks after that first result and opens automatically.

Later result screens offer both Skill Tree and Try Another Day.

The title screen shows Skill Tree only after progression exists.

Purchases subtract from the bank.

Overload banks the penalized final score.

Going home banks the cashed-out score.

Purchased nodes are permanently owned.

Purchased nodes become enabled immediately.

Purchased nodes can later be toggled independently.

Disabling a parent does not disable or unpurchase its children. Prerequisites concern ownership, not activation.

No refunds currently exist.

Reset behavior

Reset Skill Tree

Clears purchased nodes.

Clears enabled nodes.

Resets revealed nodes to only the starting node.

Keeps the tree unlocked.

Keeps the current score bank.

Does not refund anything previously spent.

Reset Full Save

Clears bank, tree, reveal state, enabled state, run history and unlock state.

Returns the game to the original first-run condition.

I would include tutorial completion in a full reset, since otherwise it is not actually a full save reset.

Initial tree and exact prototype costs

NORMAL

Cost: 50 · Passive

Increase the Overload limit by 1.

REHEARSE

Cost: 175 · Getting Ready · Adds 5 sec

Complete the rehearsal to gain +1 Overload limit for the rest of the run.

A wrong answer or timeout spawns 2 minigames.

HOLD

Cost: 225 · Automatic · Once per run

The first minigame that would fill the last open Overload slot is held back.

It spawns when a slot opens or after 5 seconds.

PLAN

Cost: 325 · Getting Ready · Adds 4 sec

Complete the sequence to stagger the next 2 double spawns.

The second minigame spawns 3 seconds later.

ADRENALINE

Cost: 425 · Automatic · Once per run

At 1 below the Overload limit, stop new minigames from spawning for 6 seconds.

Active minigames stay on screen.

SUPPRESS

Cost: 650 · Automatic · Once per run

When you would Overload, mash Space to suppress half of the active minigames.

Suppressed minigames do not count as cleared.

Architectural refactor

The largest efficiency improvement is to stop building progression around the current enhanced end-screen script.

At present, React renders an EndCard, but endScreens.js observes the DOM, hides that card, derives results from rendered elements and creates a second result screen outside React.

It also infers time from score, which stops working the moment unscored technique time exists.

Trying to attach score deposits, tree unlocks and navigation to that observer would create two competing owners of the run result. The efficient path is to move the enhanced results into React and retire the imperative observer.

Persistence model

Use a versioned local-storage object:

{
  version: 1,

  bank: 0,
  treeUnlocked: false,

  purchasedNodeIds: [],
  revealedNodeIds: [],
  enabledNodeIds: [],

  completedRuns: 0,
  highScore: 0,
  lastBankedRunId: null
}

lastBankedRunId prevents accidental duplicate deposits.

The tutorial currently uses a separate local-storage key, so storage is already part of the game’s behavior.

Result transaction

All outcomes should pass through one React function:

finishRun({
  outcome,
  rawScore,
  finalScore,
  dayElapsed,
  runElapsed,
  clearedCount,
  suppressedCount,
  peakLoad,
})

That function:

ends the run;

constructs the result;

deposits finalScore;

increments completed runs;

updates high score;

persists the result exactly once;

decides whether the tree unlock flow is required.

No score banking should happen from a render effect.

Timing refactor

The current elapsed value controls score, phase, completion, world movement and pacing.  The pacing director also derives its current phase from that same value.

Split it into:

runElapsed
dayElapsed
activeTechnique

Use explicit subsystem flags:

const dayAdvancing =
  status === 'playing'
  && !tutorialPaused
  && !orderDialogueOpen
  && !activeTechnique?.pausesDay

const spawningEnabled =
  status === 'playing'
  && directorReady
  && !tutorialPaused
  && !orderDialogueOpen
  && !activeTechnique?.pausesSpawns

Normal dialogue

The current café ordering dialogue pauses gameplay. That existing behavior can remain separate from techniques rather than being forced into the same pause definition.

Pacing refactor

Change the pacing call from:

takeSpawnBatch(director, { elapsed })

to:

takeSpawnBatch(director, {
  spawnElapsed: runElapsed,
  phaseId: currentPhase.id,
})

Then:

runElapsed controls whether another spawn is due;

phaseId controls the weights, interval and pair chance.

Delayed games from Hold It Together or Run Through the Plan should enter a small pending-spawn queue:

pendingSpawns = [
  {
    kind: 'brainFog',
    releaseAt: runElapsed + 3,
    releaseCondition: 'time',
  }
]

This avoids adding separate timers throughout the components.

Required test matrix

Progression

Final score deposits once.

Overload deposits penalized score.

Going home deposits full cashed-out score.

Purchase subtracts exact cost.

Purchase auto-enables.

Purchase reveals children.

Toggle does not alter ownership or descendants.

Capacity

Rehearsal failure: remains 6 and spawns two.

Timing

Normal play advances both clocks.

Rehearsal advances only run time.

Spawning continues during rehearsal.

Suppression advances run time but pauses day and spawning.

Maximum score remains 500 regardless of added technique time.

Suppression

Intercepts overload once.

Requires 12 presses.

Removes half of current active games.

Leaves the correct rounded-down remainder.

Does not increment cleared count.

Ordinary overload occurs normally after it is spent.

Contradiction audit

The plan preserves the established constraints:

No skill changes individual minigame difficulty.

Added scheduled time is unscored.

Scheduled techniques pause phase progression.

Spawning continues during rehearsal.

Spawning pauses during suppression.

Suppression requires player input.

Purchased nodes start enabled but remain toggleable.

Toggling does not destroy purchase or reveal state.

The tree presents itself as an actual game skill tree.

The first run is meaningfully harder because capacity begins at 5.

The starting node restores the capacity previously treated as normal.

Recognition is produced by the accumulating system, not explanatory menu copy.

The only content still missing is final dialogue wording, final animation art and later-tree nodes. None of those should delay the refactor or the first playable branch.
